# 001 — W0 scaffold: what the plan said and what npm actually shipped

**Date:** 2026-09-12 · **Wave:** W0 (T1, T3a, T3b, T4, T2) · **Status:** resolved

## Symptom

The plan (`here-is-my-end-wild-stardust.md` §1.4) pins every dependency by hand and
marks several _(verify)_. A bare `npm i` of four of them would have installed a
major the plan explicitly forbids, and two documented commands do not work as
written.

## Investigation

Registry state observed at install time (npm 11.13.0, 2026-09-09/12):

| Package             | `latest` on the registry | Installed (plan pin)  |
| ------------------- | ------------------------ | --------------------- |
| `typescript`        | **7.0.2**                | `5.9.3` (`^5.9.3`)    |
| `eslint`            | **10.10.0**              | `9.39.5` (`^9.39`)    |
| `prisma` & client   | **8.0.0-rc.13**          | `7.10.0` exact        |
| `vitest` + coverage | **5.0.0**                | `4.1.11` both         |
| `@types/node`       | `22.20.2` (24.x exists)  | `^24.13.4` (<25)      |
| `react` / `-dom`    | `19.3.0`                 | `~19.2.8` (<19.3)     |
| `three`             | `0.186.0`                | `0.185.1` (caret 0.x) |

`create-next-app@16.3.4 --help` does **not** list `--turbopack`, `--no-src-dir`,
`--no-react-compiler` or `--no-agents-md`. Probing the exact command line in a
scratch directory showed commander accepts all four with no "unknown option"
error and produces the intended end state, so the plan's command was used verbatim.

## Root cause

Three plan statements are wrong against the real tools:

1. **`npx gitleaks detect`** — no npm package provides that executable. gitleaks
   is a Go CLI (Homebrew 8.30.1 here, pinned 8.21.2 in CI).
2. **`npx playwright test --project desktop-chromium tests/e2e/smoke.spec.ts`** —
   `--project` is variadic in `@playwright/test` 1.63.0, so the spec path is
   swallowed as a second project name and the run fails with
   `Project(s) "tests/e2e/smoke.spec.ts" not found`.
3. **Bundle budget** (§7.3, home ≤ 130 kB gzip first-load) is below the floor of
   an empty Next 16.3.4 + React 19 + next-intl route, measured at 130.7 kB.

## Fix

1. Use the `gitleaks` CLI directly; `.husky/pre-commit` guards with `command -v`.
2. Use `--project=desktop-chromium` (equals form). Recorded here because the
   plan's §8.1/§9 command strings still carry the broken form.
3. Budgets in `perf.budgets.json` enforce a measured ceiling and keep the plan's
   numbers as `targetGzipBytes`; see "Bundle budget" below.

## How to detect a regression

- `npx audit-ci --config audit-ci.json` — pins and allowlist.
- `tests/unit/ci/required-checks.test.ts` — the CI contract.
- `npx tsx scripts/perf/bundle-budget.ts` — the budget gate.

### Bundle budget — ratchet policy (user decision, 2026-09-12)

§7.3's flat numbers (home ≤ 130 kB, guide ≤ 140 kB gzip first-load) are below the
framework floor: an empty route measures 130.7 kB and the W0 shell measures
154.6 kB. The user chose a **ratchet**: `firstLoadJsGzipBytes` is re-pinned at every
wave integration to the freshly measured value + 10 %, rounded up to a whole KiB,
while `targetGzipBytes` keeps §7.3's numbers and W4-T2 ratchets the ceilings down.

W0 pin: home measured 154 600 B → ceiling **171 008 B** (167.0 KiB). The guide
route is not built until W1-T4 and is pinned at that wave's integration.

### Deviations accepted at integration

- `eslint-config-prettier@^10.1.8` is in `devDependencies` but not in §1.4. It is
  genuinely used by `eslint.config.mjs` and is what stops ESLint and Prettier
  fighting. Accepted as a documented addition.
- `lib/i18n/request.ts` and `app/layout.tsx` were created by W0-T1 though §8
  assigns them to W0-T2; both were forced (the build fails without them). W0-T2
  rewrote `request.ts` and deleted `app/layout.tsx`, so the end state matches the plan.
- `tests/e2e/global-setup.ts` uses `prepareTestDatabase()` (migrate deploy →
  TRUNCATE → seed) instead of §7.2's `migrate reset --force` + `db seed`.
  Behaviourally equivalent and much faster between specs.
- `vitest.config.ts` suppresses coverage thresholds on blob/shard runs; the full
  gate is enforced by `scripts/ci/coverage.sh` via `--merge-reports`.
- The SAST job runs on `ubuntu-latest` rather than in the `semgrep/semgrep`
  container (§7.4): the Alpine image has no guaranteed bash, and every CI job body
  must be `bash scripts/ci/<step>.sh`.

### Fixed during integration

- `app/[locale]/loading.tsx` was missing from W0-T2's output though its file list
  names it. Written as a sync server component (a Suspense fallback must not be
  async) with an `sr-only` status region and `motion-safe:` pulse.
- `renovate.json` now sets `minimumReleaseAge: "7 days"` on every `packageRules`
  entry and `false` under `vulnerabilityAlerts`, so a security fix still ships
  immediately. The matching **temporary** semgrep exclusion was deleted from
  `scripts/ci/sast.sh`; `bash scripts/ci/sast.sh` prints `SAST clean`.

### Open for W1
