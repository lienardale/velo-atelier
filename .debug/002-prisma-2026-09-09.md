## Subcommand flags (from `--help`, verbatim option names)

| Command          | Options                                                                                                                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `migrate dev`    | `--config`, `--schema`, `--url`, `-n/--name`, `--create-only`                                                                                                                                                            |
| `migrate deploy` | `--config`, `--schema`                                                                                                                                                                                                   |
| `migrate diff`   | `--config`, `-o/--output`; from/to pairs `--from-empty/--to-empty`, `--from-schema/--to-schema`, `--from-migrations/--to-migrations`, `--from-config-datasource/--to-config-datasource`; flags `--script`, `--exit-code` |
| `generate`       | `--config`, `--schema`, `--sql`, `--watch`, `--generator`, `--no-hints`, `--require-models`                                                                                                                              |
| `db seed`        | `--config` (extra args after `--`)                                                                                                                                                                                       |

- `migrate diff --from-url` is **gone** (confirmed: not in `--help`).
- `--exit-code` semantics: **0** empty diff, **1** error, **2** non-empty diff.
- The CI drift check is therefore exactly:
  `npx prisma migrate diff --exit-code --from-config-datasource --to-schema prisma/schema.prisma`
  Observed on a freshly migrated database: `No difference detected.`, exit 0.
  The hand-created `citext` extension is **not** reported as drift.

## Behaviour that differs from the help text

- **`migrate dev` does NOT run `generate`**, even though its `--help` banner
  still says "trigger generators (e.g. Prisma Client)". Verified by back-dating
  `lib/generated/prisma/client.ts` (`touch -t 202601010000`) and running
  `prisma migrate dev`: the file's mtime was unchanged afterwards. It does not
  run the seed either. Hence `db:migrate` = `prisma migrate dev && prisma generate`
  and `scripts/db/local.sh` runs `prisma generate` after `migrate deploy`.
- **The CLI loads no `.env` file on its own.** `prisma.config.ts` calls
  `dotenv.config({ path: ['.env.local', '.env'], quiet: true })`. dotenv never
  overrides a variable already present in `process.env`, so an exported
  `POSTGRES_URL` (CI `env:`, `scripts/db/local.sh`) always wins over the files.

## `prisma.config.ts`

- `import { defineConfig } from 'prisma/config'` (also exports `env`).
- `PrismaConfig` keys in 7.10.0: `schema`, `migrations { path, seed, initShadowDb }`,
  `datasource { url, shadowDatabaseUrl }`, `tables`, `enums`, `views`,
  `typedSql`, `experimental`.
- A relative TypeScript import from the config (`./lib/db/env`) resolves fine.
  The `@/` alias is **not** available there — use relative paths.
- `datasource.url: readDatabaseUrls().direct ?? ''` lets `prisma generate`
  (the `postinstall` hook) run with no environment at all; `migrate` fails
  loudly on the empty string.

## Schema / generator

- `generator client { provider = "prisma-client"; output = "../lib/generated/prisma" }`
  emits `client.ts`, `browser.ts`, `enums.ts`, `models.ts`, `models/`,
  `internal/`. The one import path is `@/lib/generated/prisma/client`
  (relative `../lib/generated/prisma/client` from `prisma/` and `scripts/`,
  which run under `tsx` without the Next alias).
- `datasource db { provider = "postgresql" }` with no `url` validates in Prisma 7.
- `@db.Citext` maps to `CITEXT` in the generated SQL.

## Driver adapter

`new PrismaPg(poolOrConfig: pg.Pool | pg.PoolConfig | string, options?: { schema?: string })`
— so `new PrismaPg({ connectionString, max: 3 })` (§4.1) is a `pg.PoolConfig`.

## Migration 0001

```
npx prisma migrate dev --create-only --name init   # → prisma/migrations/20260911071112_init/
# prepend by hand, as the first statement:
#   CREATE EXTENSION IF NOT EXISTS citext;
npx prisma migrate dev                              # applied; client NOT regenerated
npx prisma generate
```

`tests/unit/db/init-migration.test.ts` asserts the line is present **and** is
the first statement; `tests/integration/schema.test.ts` asserts `pg_extension`
contains `citext` and that `"User"."email"` has `udt_name = 'citext'`.

## `$queryRaw` gotcha

The Prisma 7 query compiler cannot deserialize a Postgres `name[]` column
(`Failed to deserialize column of type 'Unknown'`). Catalog queries that
aggregate `pg_enum.enumlabel` / `pg_type.typname` must cast to `::text`.
Scalar `name` columns (`extname`, `indexname`) come back fine.

## Turbopack + Prisma 7 boot check (prisma/prisma#29025)

```
env -u POSTGRES_URL -u POSTGRES_URL_NON_POOLING npx next build   # Turbopack, Next 16.3.4 → exit 0
POSTGRES_URL=… POSTGRES_URL_NON_POOLING=… npx next start -p 3000
curl -i localhost:3000/api/health   # HTTP/1.1 200, {"ok":true,"db":true}
```

The bug did **not** reproduce with `serverExternalPackages: ['@prisma/client',
'@prisma/adapter-pg', 'pg']` and the `prisma-client` generator. **No fallback
was applied** (neither `prisma-client-js` nor `next build --webpack`), so no
`002-prisma-turbopack-*.md` note exists. If the CI `build` job's boot check
ever fails with a module-resolution error on the generated client, that note
is where the fallback gets recorded (§4.1).

The build succeeds **without** any database variable because
`lib/db/prisma.ts` constructs the client lazily (on first property access):
`next build` imports route modules to collect metadata, and an eager client
would turn "no database configured" into a build failure.

## `nvm` inside `npm run`

`npm run <script>` exports `npm_config_prefix`, and `nvm use` then refuses to
run (`nvm is not compatible with the "npm_config_prefix" environment
variable`, exit 11). A script that sources nvm under `set -e` dies there.
`scripts/db/local.sh` therefore only reaches for nvm when `node` is not
already on PATH, and does so before `set -euo pipefail`.

## How to detect a regression

- `tests/unit/db/init-migration.test.ts` — the citext line (unit, no Docker).
- `tests/integration/schema.test.ts` — extension, column types, cascades.
- `tests/unit/deploy/migrate-on-deploy.test.ts` — `postinstall` and the
  `prisma generate &&` prefix on `typecheck`.
- CI `build` job boot check — `/api/health` must return `{ok:true, db:true}`.
